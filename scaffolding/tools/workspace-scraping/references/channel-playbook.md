# 子 Agent 调度工作流

本文件用于把工作区的来源质量分级和子 `Agent`（代理）分工规则落地为可执行调度流程。适用场景包括多来源数据采集、同一变量存在多个口径、字段缺失需要补采、需要并行检索官方源和第三方源的项目。

## 调度目标

- 提高多渠道采集效率，避免一个 `Agent`（代理）在不同来源之间反复切换。
- 保证每个变量都有明确来源、质量等级、核验状态和失败记录。
- 让官方源优先，弱来源只做线索或异常排查，不污染最终数据。
- 在进入爬虫、抓取、逆向计算或批量下载前，先完成变量确认表。
- 让汇总子 `Agent`（代理）能按统一格式合并结果、处理冲突并完成验收。

## 来源质量顺序

```text
官方 > 官方新闻 > 第三方新闻 > 论文 > 逆向计算 > 论坛 > 其他渠道
```

使用原则：

- 同一变量存在多个来源时，默认采用质量等级更高的来源。
- 低等级来源不能覆盖高等级来源，只能作为线索、补充或异常排查依据。
- 逆向计算必须记录公式、输入值、输入来源、计算口径、时间范围和误差风险。
- 来源冲突不能直接平均或随意选择，必须进入冲突处理流程。

## 何时必须派遣多个子 Agent

满足任一条件时，应拆分子 `Agent`（代理）并行处理：

- 变量表中存在 3 个以上变量，且来源类型不完全相同。
- 同一变量可能同时出现在官网、公告、新闻、报告或数据库中。
- 目标包含附件、`PDF`（便携式文档格式）、表格、网页列表或分页。
- 官方源缺失，必须用官方新闻、第三方新闻或逆向计算补齐。
- 需要核验历史时间序列、同比环比、口径变化或跨来源冲突。
- 预计采集页面超过 10 页，或存在分页、并发、断点续跑需求。

不建议拆分的情况：

- 只有 1 到 2 个简单变量，且来源明确、页面稳定。
- 用户只是要求普通问答、单次搜索或不落盘的快速判断。
- 变量表尚未确认。此时应先完成变量确认，不进入采集调度。

## 调度前置输入

调度前至少准备以下材料：

| 输入 | 必需 | 说明 |
| --- | --- | --- |
| 变量确认表 | 必需 | 包含变量名、字段含义、单位、类型、来源优先级、必填性、清洗规则、可接受缺失条件、备注 |
| 目标范围 | 必需 | 采集对象、时间范围、地域范围、主体范围 |
| 交付格式 | 必需 | `xlsx`（Excel 表格）、`csv`（逗号分隔值文件）、`jsonl`（逐行 JSON 文件）或其他格式 |
| 已知来源 | 可选 | 用户提供的网址、文件、数据库、公告入口 |
| 旧数据 | 可选 | 历史版本，用于字段对齐、增量采集和异常对比 |
| 约束条件 | 可选 | 登录限制、频率限制、禁止来源、必须来源、人工确认门槛 |

若变量确认表缺失或未确认，应暂停调度，先生成空白变量确认表并等待用户确认。

## 变量到渠道的拆分方法

汇总前置 `Agent`（代理）或主 `Agent`（代理）先逐行读取变量确认表，并为每个变量标注推荐渠道。

| 变量特征 | 推荐优先渠道 | 说明 |
| --- | --- | --- |
| 法定披露、注册信息、公告数据 | 官方源 | 官网、公告、开放接口、官方数据库优先 |
| 新闻稿、活动动态、官方表态 | 官方新闻 | 官方新闻中心、官方媒体账号、官方发布平台 |
| 行业事件、市场口径、第三方披露 | 第三方新闻 | 用于补充、追踪首发和交叉验证 |
| 论文、报告、白皮书中的统计值 | 文献提取 | 记录页码、表格编号和提取方式 |
| 由时间序列或公开公式推导 | 逆向计算 | 必须保留公式和输入来源 |
| 社区爆料、论坛讨论、问答线索 | 弱来源核验 | 只作为线索或异常排查，不直接进入正式值 |
| 多来源结果需要合并 | 汇总 | 去重、冲突处理、质量等级和最终验收 |

一个变量可以分配给多个渠道，但必须指定主渠道和补充渠道。主渠道负责给出最终候选值，补充渠道负责核验或补缺。

## 子 Agent 类型与职责

### 官方源子 Agent

采集范围：

- 官网页面。
- 公告和披露文件。
- 开放接口。
- 官方数据库。

输入：

```text
目标主体：
变量清单：
时间范围：
官方入口：
必须字段：
可接受缺失条件：
```

输出：

```text
采集范围：
字段结果：
来源链接或文件：
来源质量等级：官方
采集时间：
核验状态：
失败项：
下一步建议：
```

### 官方新闻子 Agent

采集范围：

- 官方新闻稿。
- 官方动态。
- 官方媒体账号。
- 官方发布平台。

重点记录：

- 发布时间。
- 发布主体。
- 原文链接。
- 引用字段。
- 是否与官方源一致。

### 第三方新闻子 Agent

采集范围：

- 行业媒体。
- 新闻站点。
- 转载链路。
- 数据转载源。

重点记录：

- 首发来源。
- 转载来源。
- 发布时间差异。
- 与官方源或官方新闻的冲突项。
- 是否仅作为补充线索。

### 文献提取子 Agent

采集范围：

- 论文。
- 研究报告。
- 白皮书。
- `PDF`（便携式文档格式）。
- 附件表格。

重点记录：

- 页码。
- 表格编号。
- 图表编号。
- 提取方式。
- 字段口径。
- 原始文件保存位置。

### 逆向计算子 Agent

采集范围：

- 公开口径公式。
- 时间序列。
- 同比环比。
- 总量与分项反推。
- 多来源交叉推算。

输出必须包含：

```text
目标变量：
计算公式：
输入值：
输入来源：
时间范围：
单位换算：
误差风险：
是否可进入正式表：
```

### 弱来源核验子 Agent

采集范围：

- 论坛。
- 社区。
- 问答站。
- 非正式渠道。

限制：

- 不得直接给最终正式值。
- 必须标记为弱来源。
- 必须说明为什么需要使用弱来源。
- 必须给出后续高质量来源核验建议。

### 汇总子 Agent

职责：

- 合并所有子 `Agent`（代理）输出。
- 字段对齐。
- 去重。
- 来源质量排序。
- 冲突处理。
- 缺失原因记录。
- 生成最终数据表。
- 进行交付前验收。

汇总输出：

```text
字段清单：
最终值：
采用来源：
备选来源：
来源质量等级：
采集时间：
核验状态：
缺失说明：
冲突处理说明：
最终文件位置：
```

## 派遣流程

### 第 1 步：读取变量确认表

检查每个变量是否包含必需字段：

- 变量名。
- 字段含义。
- 单位。
- 数据类型。
- 来源优先级。
- 是否必填。
- 清洗规则。
- 可接受缺失条件。

若缺失关键信息，先补变量表，不派遣采集子 `Agent`（代理）。

### 第 2 步：建立变量-渠道矩阵

为每个变量建立矩阵：

| 变量名 | 主渠道 | 补充渠道 | 必填 | 可接受缺失条件 | 备注 |
| --- | --- | --- | --- | --- | --- |
| 待填写 | 官方源 | 官方新闻、第三方新闻 | 是 | 无官方披露时允许缺失 | 待填写 |

矩阵用于决定哪些子 `Agent`（代理）可以并行，哪些必须等待上游结果。

### 第 3 步：判断并行与依赖

可并行：

- 官方源、官方新闻、第三方新闻互不依赖时。
- 文献提取与网页采集互不依赖时。
- 弱来源核验仅作为线索时。

需要等待：

- 逆向计算需要官方源或文献输入值时。
- 汇总子 `Agent`（代理）必须等待主要渠道完成后再执行。
- 低质量来源准备覆盖高质量来源时，必须等待冲突处理。

### 第 4 步：派遣子 Agent

每个子 `Agent`（代理）收到任务时，应包含：

```text
任务名称：
变量清单：
目标范围：
来源范围：
输出格式：
质量等级：
失败记录要求：
保存位置：
```

输出必须保存或记录到子项目 `原始数据/`、`原始文件/` 或 `doc/采集策略.md` 指定的位置。

### 第 5 步：汇总与冲突处理

汇总子 `Agent`（代理）按以下顺序处理：

1. 按变量名和时间范围对齐字段。
2. 去除完全重复来源。
3. 按来源质量等级排序。
4. 比较单位、口径、时间范围和统计边界。
5. 对冲突值执行冲突处理流程。
6. 标记最终采用值和备选值。
7. 记录缺失原因和下一步建议。

### 第 6 步：验收交付

最终交付前检查：

- 变量表是否已确认。
- 必填字段是否完整。
- 缺失字段是否写明原因。
- 来源链接或文件是否可追踪。
- 来源质量等级是否已标注。
- 采集时间是否已记录。
- 核验状态是否已标注。
- 最新版数据是否位于子项目根目录。
- 原始数据和原始文件是否归档。

## 冲突处理流程

当同一变量出现多个候选值时，按以下顺序判断：

1. 来源等级高者优先。
2. 同等级来源中，原始出处优先于转载。
3. 同等级来源中，口径更接近变量定义者优先。
4. 同等级来源中，时间范围更匹配者优先。
5. 同等级来源中，可复核性更强者优先。
6. 若仍无法判断，保留多个候选值并标记为“待人工确认”。

冲突记录模板：

```text
变量名：
候选值 A：
来源 A：
质量等级 A：
候选值 B：
来源 B：
质量等级 B：
冲突原因：
采用值：
采用理由：
是否需要人工确认：
```

## 缺失处理流程

必填字段缺失时，按以下顺序补采：

1. 再查官方源。
2. 查官方新闻。
3. 查第三方新闻。
4. 查论文、报告或 `PDF`（便携式文档格式）。
5. 判断是否可以逆向计算。
6. 使用弱来源寻找线索。
7. 若仍缺失，记录缺失原因、已尝试渠道和下一步建议。

缺失记录模板：

```text
变量名：
是否必填：
已尝试渠道：
失败原因：
可接受缺失条件：
是否满足可接受缺失：
下一步建议：
```

## 交付文件建议

多子 `Agent`（代理）任务建议在子项目中形成以下文件：

```text
目标项目/
├─ doc/
│  ├─ 变量确认表.csv
│  ├─ 采集策略.md
│  ├─ 子Agent调度表.md
│  └─ 目录说明.md
├─ 原始数据/
│  ├─ 官方源_原始结果.jsonl
│  ├─ 新闻源_原始结果.jsonl
│  └─ 文献提取_原始结果.jsonl
├─ 原始文件/
├─ 旧数据/
├─ try/
└─ latest.xlsx
```

`子Agent调度表.md` 可记录每个子 `Agent`（代理）的任务、输入、输出、状态和失败项。

## 子 Agent 调度表模板

```markdown
# 子 Agent 调度表

| 任务 | 子 Agent | 变量 | 主渠道 | 补充渠道 | 状态 | 输出位置 | 失败项 | 下一步 |
| --- | --- | --- | --- | --- | --- | --- | --- | --- |
| 待填写 | 官方源子 Agent | 待填写 | 官方源 | 官方新闻 | 待执行 | 待填写 | 无 | 待填写 |
```

## 最小调度示例

变量表中包含公司注册资本、年度收入和新闻发布日期：

```text
注册资本 -> 官方源子 Agent
年度收入 -> 官方源子 Agent + 文献提取子 Agent
新闻发布日期 -> 官方新闻子 Agent
缺失年度收入 -> 逆向计算子 Agent
全部结果 -> 汇总子 Agent
```

汇总子 `Agent`（代理）最终输出 `latest.xlsx`，并在表中标注每个字段的来源、质量等级、采集时间和核验状态。
