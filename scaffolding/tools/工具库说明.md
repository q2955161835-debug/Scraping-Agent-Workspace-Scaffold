# tools 工具库说明

## 用途
- `tools/`（工具库）存放本工作区常用技能实体目录、可复用脚本和工作区专用技能。
- 工具库服务于实际爬虫任务，优先减少重复建目录、重复建变量表、重复做结构检查。
- 当脚手架作为根目录 `scaffolding/` 子目录使用时，工具库路径为 `scaffolding/tools/`，实际目标子项目默认创建在上一级工作区根目录。

## 目录
- `skills/`：常用技能实体目录，随仓库提交，避免其他机器 clone（克隆）后出现本地绝对路径失效。
- `scripts/`：实际爬虫任务常用复用脚本。
- `workspace-scraping/`：本工作区专用 `skill`（技能），用于指导子项目创建、变量确认、渠道派遣和数据验收。
  - `workspace-scraping/references/subagent-prompt-templates.md`：子 `Agent`（代理）派遣提示词模板，按来源等级和任务目标注入。
  - `workspace-scraping/references/channel-playbook.md`：多渠道派遣、任务清单去重和冲突处理流程。
  - `workspace-scraping/references/dataset-acceptance.md`：交付验收清单。

## 技能目录管理
- 技能目录命名应与原技能名保持一致或保持可识别。
- 新增或更新技能目录时，需要确认来源路径可信，并在 `doc/项目地图.md` 中更新工具库清单。
- 上传 GitHub（代码托管平台）前需要确认技能目录不是符号链接，并扫描真实密钥、`token`（令牌）、`cookie`（会话凭据）等敏感信息。
- `tools/scripts/Link-Skills.ps1` 保留为旧版本地软连接重建脚本；当前仓库默认提交真实技能目录。

## 可复用脚本管理
- 脚本必须只处理工作区内的项目结构、变量表、检查任务或中间文件整理。
- 脚本参数必须明确，避免依赖当前目录猜测危险路径。
- 新增脚本后，在本文件和 `tools/workspace-scraping/SKILL.md` 中补充用途。

## 脚本清单
- `scripts/scaffold_project.py`：跨平台创建目标子项目目录骨架。
- `scripts/scaffold_project.py` 默认生成 `doc/任务清单.md`，用于登记 URL（统一资源定位符）、文件、去重键、状态、输出位置和失败项。
- `scripts/create_variable_template.py`：跨平台创建空白变量确认表。
- `scripts/validate_workspace.py`：跨平台检查脚手架结构。
- `scripts/New-ScrapingProject.ps1`：Windows（微软视窗系统）版子项目创建脚本。
- `scripts/New-ScrapingProject.ps1` 默认生成 `doc/任务清单.md`，与 Python（编程语言）版本保持一致。
- `scripts/New-VariableTemplate.ps1`：Windows（微软视窗系统）版变量确认表脚本。
- `scripts/Test-ScrapingWorkspace.ps1`：Windows（微软视窗系统）版结构检查脚本。
- `scripts/Link-Skills.ps1`：Windows（微软视窗系统）版旧版常用技能软连接重建脚本。
